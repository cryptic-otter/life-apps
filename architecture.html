Supabase Backend-as-a-Service — Hosted PostgreSQL + Auth

Auth

  • Email + password provider (built-in)
  • Sessions stored in HTTP-only cookies (SSR-safe via @supabase/ssr)
  • JWT issued per user, contains auth.uid()
  • Email confirmation via /api/auth/callback
  • Redirect URLs configured in Supabase dashboard
  • Sign-out clears cookie + redirects to login

Request Lifecycle — Authenticated Page Load

1
User navigates to /diet. Browser sends request with session cookie to Vercel edge.
2
src/middleware.ts reads the cookie and calls Supabase to verify the session. No valid session → 302 redirect to /auth/login. Valid session → request continues.
3
app/diet/page.tsx (Server Component) runs on a Vercel serverless function. It calls createClient() (server), which attaches the user’s JWT to the Supabase query.
4
Supabase evaluates the RLS policy: auth.uid() = user_id. Returns only this user’s diet_entries rows for today.
5
Next.js renders HTML server-side (including the DietForm client component shell) and streams it to the browser. No loading spinner — data is in the initial HTML.
6
User submits “+ Log food” form → browser calls the addEntry() Server Action (an RPC to Vercel). Action inserts row into Supabase, calls revalidatePath('/diet'), page re-renders with fresh data.

Key File Reference

src/middleware.ts

Edge function. Checks session on every request. Protects all routes except /auth/*.

src/lib/supabase/server.ts

Server-side Supabase client. Reads/writes auth cookies via Next.js cookies(). Used in all Server Components and Server Actions.

src/lib/supabase/client.ts

Browser Supabase client. Used only in 'use client' components (login flow, auth state).

src/app/api/auth/callback/route.ts

Exchanges the Supabase auth code for a session cookie after the email confirmation link is clicked.

src/components/Nav.tsx

Server Component. Reads session to show/hide nav. Sign-out uses a Server Action — no client JS needed.

supabase/migrations/001_initial.sql

Full DB schema. Paste into Supabase SQL Editor to create the three tables + RLS policies.

src/app/*/page.tsx

Each tracker page is a Server Component with inline Server Actions for mutations. Data fetched at request time.

src/app/*/[Name]Form.tsx

Client Components for the add-entry forms. Marked 'use client' for controlled inputs and local open/close state.

.env.local.example

Template for required environment variables. Copy to .env.local locally and add to Vercel dashboard for production.
